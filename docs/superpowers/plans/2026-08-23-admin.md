# Admin Panel Implementation Plan (spec phase 10)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the Flask-Admin panel with SQLAdmin bound to the same async models and engine the bot already uses, so the repository has one stack and one dependency set instead of two.

**Architecture:** SQLAdmin mounts onto the existing FastAPI app in `bot/entrypoints/api.py`, sharing the dishka-built `AsyncEngine`. The `admin`, `role` and `roles_admins` tables move from `db.create_all()` at import time into Alembic. Passwords are hashed with stdlib `hashlib.scrypt`. When it lands, the entire `admin/` package and nine dependencies are deleted.

**Tech Stack:** SQLAdmin 0.31.0, `itsdangerous` 2.2.0, `python-multipart` 0.0.32, SQLAlchemy 2 async, Alembic, FastAPI.

**Spec:** `docs/superpowers/specs/2026-08-23-scalable-architecture-design.md` — section 15 (admin panel), section 20 (dependencies), section 21 phase 10.

---

## What is being replaced, precisely

`admin/` is 26 files running a **parallel synchronous stack**: Flask, Flask-Admin, Flask-Security-Too, Flask-Caching, Flask-Babel, Flask-SQLAlchemy, psycopg2, gunicorn and tablib — nine dependencies that exist for nothing else in the repository. It duplicates the models (`RoleModel`, `AdminModel` declared against `db.Model`), the configuration (`admin/config.py` reads `os.getenv` directly instead of the pydantic `Settings`), the engine, and the connection pool. It touches the bot at exactly one line: `from bot.database.models import UserModel`.

It also carries **spec defect 11**: `admin/app.py` ends in

```python
with app.app_context():
    init_db()
```

so the `admin`, `role` and `roles_admins` tables are created by `db.create_all()` at **import time**, outside Alembic, seeded with a superuser from `DEFAULT_ADMIN_EMAIL` / `DEFAULT_ADMIN_PASSWORD`. Alembic does not know those tables exist. Any `alembic revision --autogenerate` run while they are present will happily emit `drop_table` for all three.

## Feature parity is the bar, not pixel parity

Everything below exists today and must exist afterwards. Read this table before writing any view — it is the acceptance criterion.

| Surface | Today (Flask-Admin) | Required after |
|---|---|---|
| Users list | `id, username, first_name, last_name, language_code, is_admin, is_suspicious, is_block, is_premium, created_at` | same columns |
| Users search | `id, username, first_name, last_name` | same |
| Users filters | `is_admin, is_suspicious, is_block, is_premium, created_at` | same |
| Users sort | `created_at` descending by default | same |
| Users actions | edit, delete, view details; **no create** | same |
| Admins | full CRUD, password write-only, `confirmed_at` excluded from the form | same |
| Roles | list only for superusers — no create/edit/delete | same |
| Dashboard | total users, new users in the last day, an always-zero order count, and the default credentials | total users, new users in the last day, **drop the order count** |
| Login | session login at `/admin/login/` | session login |

Two deliberate reductions, both stated rather than discovered later:

1. **Export becomes CSV only.** Flask-Admin offers csv/xlsx/json/yaml through `tablib`, which is one of the nine dependencies being deleted. SQLAdmin exports CSV natively. Keeping xlsx would mean keeping `tablib[xlsx]` and its openpyxl tree for one button. The bot's `/export_users` command already produces CSV by a different path and is unaffected.
2. **The order count disappears.** `get_orders_count()` returns a hardcoded `0` and there is no order model anywhere in the repository. Reproducing a fake zero is worse than removing it.

## Global Constraints

- Python floor **3.14**; all tooling through `uv` — never bare `pip`. Run `uv sync` after every `pyproject.toml` change, and commit `uv.lock` with it.
- Logging is `from loguru import logger`; stdlib `logging` is forbidden.
- ruff `select = ["ALL"]`, line-length 120, `fix = true`, `unsafe-fixes = false`. **`uv run ruff check .` mutates files** — run it before reading your diff.
- mypy strict, 0 errors.
- **No tests.** Do not write tests, do not create `tests/`. Verify with throwaway scripts and live runs, deleted afterwards.
- Conventional commits; **never** a `Co-Authored-By` trailer.
- **Runtime annotation hazard** — this codebase's most-repeated defect (10 occurrences so far). dishka, FastAPI, aiogram and SQLAlchemy resolve annotations at RUNTIME via `get_type_hints()`. Any type in a route signature, a FastAPI dependency, a dishka provider or a SQLAlchemy `Mapped[...]` must be a real module-level import, never under `if TYPE_CHECKING:`. Where ruff's TC rules push a runtime-needed import into `TYPE_CHECKING`, add a targeted `# noqa: TC00x`, as `bot/core/di.py` and `bot/handlers/payments.py` already do.
- A new model **must** be re-exported from `bot/database/models/__init__.py`. Alembic autogenerate reads `Base.metadata` through that import and will emit a `drop_table` for anything missing.
- Passwords use stdlib `hashlib.scrypt`. No new hashing dependency, and no hand-rolled scheme.

```python
from __future__ import annotations

import hashlib
import hmac
import secrets

# scrypt parameters. n=2**14 with r=8, p=1 is the interactive-login profile from RFC 7914
# and costs roughly 100 ms per hash — slow enough to make offline guessing expensive,
# fast enough that a login does not feel broken.
_N = 2**14
_R = 8
_P = 1
_SALT_BYTES = 16
_KEY_LEN = 64


def hash_password(password: str) -> str:
    """A `scrypt$<salt-hex>$<digest-hex>` string, safe to store verbatim.

    stdlib scrypt rather than a dependency: passlib and argon2 would each add a tree
    for one function, and the spec is explicit that this must not be hand-rolled —
    which it is not, since `hashlib.scrypt` is the primitive.
    """
    salt = secrets.token_bytes(_SALT_BYTES)
    digest = hashlib.scrypt(password.encode(), salt=salt, n=_N, r=_R, p=_P, dklen=_KEY_LEN)
    return f"scrypt${salt.hex()}${digest.hex()}"


def verify_password(password: str, stored: str) -> bool:
    """Constant-time verification. Returns False for anything malformed.

    `hmac.compare_digest`, not `==`: a plain comparison short-circuits on the first
    differing byte and leaks the digest to a timing attack. This project has already
    fixed that exact bug twice — on the webhook secret and on the Mini App initData
    signature — so it is not a hypothetical here.
    """
    try:
        scheme, salt_hex, digest_hex = stored.split("$")
    except ValueError:
        return False
    if scheme != "scrypt":
        return False
    try:
        salt = bytes.fromhex(salt_hex)
        expected = bytes.fromhex(digest_hex)
    except ValueError:
        return False
    candidate = hashlib.scrypt(password.encode(), salt=salt, n=_N, r=_R, p=_P, dklen=len(expected))
    return hmac.compare_digest(candidate, expected)
```

- [ ] **Step 3: Create `bot/admin/auth.py`**

```python
# ruff: noqa: TC001, TC002 - SQLAdmin and Starlette resolve these at runtime
from __future__ import annotations

from loguru import logger
from sqladmin.authentication import AuthenticationBackend
from sqlalchemy import select
from sqlalchemy.ext.asyncio import AsyncSession, async_sessionmaker
from starlette.requests import Request
from starlette.responses import RedirectResponse

from bot.admin.security import verify_password
from bot.database.models import AdminModel

SESSION_KEY = "admin_email"


class AdminAuth(AuthenticationBackend):
    """Session login for the panel.

    Holds a sessionmaker rather than a session: SQLAdmin calls these methods per
    request, outside any dishka REQUEST scope, so each one opens and closes its own.
    """

    def __init__(self, secret_key: str, sessionmaker: async_sessionmaker[AsyncSession]) -> None:
        super().__init__(secret_key=secret_key)
        self._sessionmaker = sessionmaker

    async def login(self, request: Request) -> bool:
        form = await request.form()
        email = str(form.get("username", ""))
        password = str(form.get("password", ""))

        async with self._sessionmaker() as session:
            admin = (await session.execute(select(AdminModel).filter_by(email=email))).scalar_one_or_none()

        # Verify even when the row is missing, against a throwaway hash, so a request
        # for an unknown email costs the same time as one for a known email. Returning
        # early here would turn the panel into an account-enumeration oracle.
        stored = admin.password if admin is not None else "scrypt$00$00"
        ok = verify_password(password, stored)
        if not ok or admin is None or not admin.active:
            logger.warning(f"admin login rejected | email: {email}")
            return False

        request.session.update({SESSION_KEY: admin.email})
        logger.info(f"admin login | email: {admin.email}")
        return True

    async def logout(self, request: Request) -> bool:
        request.session.clear()
        return True

    async def authenticate(self, request: Request) -> bool | RedirectResponse:
        email = request.session.get(SESSION_KEY)
        if not email:
            return False
        # Re-read on every request rather than trusting the cookie: deactivating an
        # admin must take effect immediately, not whenever their session happens to
        # expire.
        async with self._sessionmaker() as session:
            admin = (await session.execute(select(AdminModel).filter_by(email=email))).scalar_one_or_none()
        return admin is not None and admin.active
```

```python
from __future__ import annotations

from typing import Any

from sqladmin import ModelView
from starlette.requests import Request

from bot.admin.security import hash_password
from bot.database.models import AdminModel, RoleModel, UserModel


class UserAdmin(ModelView, model=UserModel):
    name = "User"
    name_plural = "Users"
    icon = "fa-solid fa-users"

    # Mirrors the Flask panel's column_list exactly — see the parity table in the plan.
    column_list = [
        UserModel.id,
        UserModel.username,
        UserModel.first_name,
        UserModel.last_name,
        UserModel.language_code,
        UserModel.is_admin,
        UserModel.is_suspicious,
        UserModel.is_block,
        UserModel.is_premium,
        UserModel.created_at,
    ]
    column_searchable_list = [UserModel.id, UserModel.username, UserModel.first_name, UserModel.last_name]
    column_sortable_list = [UserModel.id, UserModel.created_at]
    column_default_sort = ("created_at", True)

    # No create: a Telegram user row is written by AuthMiddleware when someone messages
    # the bot. Hand-creating one would produce a row with an id that belongs to nobody.
    can_create = False
    can_edit = True
    can_delete = True
    can_view_details = True
    can_export = True


class RoleAdmin(ModelView, model=RoleModel):
    name = "Role"
    name_plural = "Roles"
    icon = "fa-solid fa-tags"

    column_list = [RoleModel.id, RoleModel.name, RoleModel.description]
    # Read-only, as in the Flask panel: the two roles are seeded by the migration and
    # the code checks them by name, so a renamed role silently removes access.
    can_create = False
    can_edit = False
    can_delete = False
    can_view_details = True
    can_export = False


class AdminAdmin(ModelView, model=AdminModel):
    name = "Admin"
    name_plural = "Admins"
    icon = "fa-solid fa-user-shield"

    column_list = [AdminModel.id, AdminModel.email, AdminModel.first_name, AdminModel.last_name, AdminModel.active]
    column_searchable_list = [AdminModel.email, AdminModel.first_name, AdminModel.last_name]
    # `password` appears in NO list: not in column_list, not in details. It holds a
    # digest rather than a password, but rendering it hands an attacker with read
    # access something to attack offline.
    column_details_exclude_list = [AdminModel.password]
    form_columns = [AdminModel.email, AdminModel.first_name, AdminModel.last_name, AdminModel.active, AdminModel.password]

    can_create = True
    can_edit = True
    can_delete = True
    can_view_details = True
    can_export = False

    async def on_model_change(self, data: dict[str, Any], model: Any, is_created: bool, request: Request) -> None:  # noqa: ANN401, FBT001
        """Hash whatever was typed into the password field before it is stored.

        Without this the form value is written verbatim and every admin password is
        stored in plaintext. An empty field on edit means "leave it alone" — otherwise
        editing an admin's name would blank their password.
        """
        password = data.get("password")
        if password:
            data["password"] = hash_password(str(password))
        elif not is_created:
            data.pop("password", None)
```

- [ ] **Step 1b: Gate Roles and Admins on the `superuser` role**

The Flask panel restricted both `RoleView` and `AdminView` to admins holding the
`superuser` role (`RoleView.is_accessible` checks `current_user.has_role("superuser")`).
Reproduce it — without this, every admin can create admins, which is a privilege
escalation the old panel did not have.

SQLAdmin supports this directly: `ModelView.is_accessible(self, request: Request) -> bool`
(verified against the installed version, alongside `is_visible` with the same signature).
Add a mixin both views use:

```python
class SuperuserOnly:
    """Restrict a view to admins holding the `superuser` role.

    `is_visible` as well as `is_accessible`: without it the menu entry renders for
    everyone and only 403s on click, which reads as a broken panel rather than a
    permission boundary.
    """

    def _is_superuser(self, request: Request) -> bool:
        return bool(request.session.get(SUPERUSER_SESSION_KEY))

    def is_accessible(self, request: Request) -> bool:
        return self._is_superuser(request)

    def is_visible(self, request: Request) -> bool:
        return self._is_superuser(request)
```

Have `AdminAuth.login` (Task 2) put the role into the session when it authenticates —
`request.session[SUPERUSER_SESSION_KEY] = any(r.name == "superuser" for r in admin.roles)`
— and `authenticate` refresh it from the database on every request, so revoking the
role takes effect immediately rather than at session expiry. `AdminModel.roles` is
already `lazy="selectin"`, so the roles come back with the admin in one query.

Verify as a contrast: a `superuser` admin sees Roles and Admins; a plain `user` admin
gets neither in the menu **and** a 403 on the direct URL. Checking only the menu proves
nothing — a hidden-but-reachable view is the bug.

## Task 5: Dashboard

**Files:**
- Create: `bot/admin/dashboard.py`

**Interfaces:**
- Consumes: `UserModel`.
- Produces: `DashboardView(BaseView)` exposed at `/`.

- [ ] **Step 1: Create the view**

```python
# ruff: noqa: TC002 - SQLAdmin resolves the view signature at runtime
from __future__ import annotations

import datetime

from dishka import Scope
from sqladmin import BaseView, expose
from sqlalchemy import func, select
from sqlalchemy.ext.asyncio import AsyncSession
from starlette.requests import Request
from starlette.responses import Response

from bot.database.models import UserModel

NEW_USER_WINDOW_DAYS = 1


class DashboardView(BaseView):
    name = "Dashboard"
    icon = "fa-solid fa-chart-line"

    @expose("/", methods=["GET"])
    async def index(self, request: Request) -> Response:
        since = datetime.datetime.now(datetime.UTC).replace(tzinfo=None) - datetime.timedelta(
            days=NEW_USER_WINDOW_DAYS,
        )
        container = request.app.state.dishka_container
        async with container(scope=Scope.REQUEST) as rc:
            session = await rc.get(AsyncSession)
            total = (await session.execute(select(func.count()).select_from(UserModel))).scalar_one()
            recent = (
                await session.execute(
                    select(func.count()).select_from(UserModel).where(UserModel.created_at >= since),
                )
            ).scalar_one()
        # `BaseView` has no `templates` attribute of its own (checked). SQLAdmin puts the
        # Jinja environment on the app during `Admin(...)` construction — read how the
        # installed version exposes it (`request.app.state`, or the templates object the
        # Admin instance holds) and use that. Do NOT build a second Jinja environment:
        # the point of `templates_dir` is that your template can extend SQLAdmin's own
        # `layout.html`, which only its environment can resolve.
        return templates.TemplateResponse(
            request,
            "dashboard.html",
            {"total_users": total, "new_users": recent, "since": since},
        )
```

`created_at` is a naive-UTC column by this table's convention (see `bot/database/models/base.py`), so the comparison value is made naive too. Passing an aware datetime raises at the driver.

- [ ] **Step 2: Add the template**

**Do not reproduce the old dashboard's credential display.** `admin/templates/admin/index.html` renders `DEFAULT_ADMIN_EMAIL` and `DEFAULT_ADMIN_PASSWORD` on the page. That prints the default administrator's password into every browser that reaches the panel, including before login in some flows. It is not a feature to carry over; note the removal in your report.

- [ ] **Step 3: Verify the counts are real**
